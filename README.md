# 微博网页数据读取 Agent

给定微博原帖，或指定账号 UID 和日期，读取主评论及楼中楼，保留原话，筛出值得回应的候选，并为能在原页核对的评论保存整屏截图。直接打开 `reader.js` 可以看采集实现，其他程序从 `agent.js` 的 `runAgent` 调用完整流程。

## 四个对话分别贡献了什么

| 历史对话标题 | 从对话中提炼的需求和经验 | 本项目的处理 |
| --- | --- | --- |
| 整理雷军小米澎湃账号评论 | 正文指定的主体是雷军和小米澎程。按账号、日期找帖，保留具体汽车问题，按大类整理。原任务还要求微博、抖音及附图 Word。历史复盘发现当天截止时间、页面总数和实扫数需要分别记录。 | 用可替换的数字 UID 锁定微博账号，以北京时间过滤发帖日期，记录实际执行截止时刻。按原帖和问题类别组织结果。 |
| 检索各平台软件制作 | 对话后来形成了“舆见”桌面工具。一次复盘中页面显示 11 条、程序识别 6 条、入选 4 条、合格截图仅 2 张。还提出用程序做读取、去重和证据绑定，降低模型调用成本。 | 两种排序分别翻页，按平台评论 ID 去重。分别给出已读数、入选数和有图数。默认筛选在本地运行，可替换。 |
| 筛选微博评论中的提问 | 给定一条微博，需要找出折叠回复里的提问并逐条截图。历史操作记录中出现过回复弹窗、虚拟滚动列表和离开视口的目标。该对话最后一次执行中断。 | 分页读回复列表，截图阶段再打开对应楼层。核对作者、正文、父楼及可见区域，保存浏览器当前视口的 PNG。 |
| 整理小米澎程网友问题与抱怨 | 为回应网友而找具体问题，后来聚焦官方帖子下的增程器讨论，要求“一条问题、一个链接、一张截图”。历史对话涉及亏电油耗、噪声、保养等主题，外链图片曾无法打开。 | 主题可配置；保留提问、抱怨、建议等多重标签，每条入选评论保留原帖链接。截图保存在本地，原话、官方回应和二手转述不会混作同一条评论。 |

本次交付聚焦微博读取核心。报告格式为 JSON 和可离线打开的 HTML。抖音适配、Word 排版和历史桌面应用都属于旧项目范围。

## 快速运行

需要 Google Chrome、Node.js 22 或更高版本。安装过 WorkBuddy 的 Mac 可以先运行 `./weibo --help`。启动脚本会查找本机已有的 Node 和 Playwright。其他环境在本目录运行 `npm install`，使用 `node cli.js` 代替 `./weibo` 也可以。

首次登录后，这个专用 Chrome 目录会保留会话。登录窗口能看到目标微博评论后，回到终端按回车。

```sh
./weibo login
./weibo scan 'https://weibo.com/1749127163/Rc88BhlAZ' --kind 提问
```

按账号找指定日期发布的微博，读取这些帖子的当前可见评论。以下示例检索雷军账号关于增程器、亏电或保养的提问与抱怨。

```sh
./weibo scan --uid 1749127163 --from 2026-07-28 --to 2026-07-28 \
  --topic 增程器 --topic 亏电 --topic 保养 --kind 提问 --kind 抱怨
```

- 多个账号可重复使用 `--uid`，请从对应官方主页确认数字 UID。多个原帖链接可以并列传入。
- 日期约束作用于账号时间线上的**发帖时间**。单帖链接直接读取；两个入口可以混用。当天的上限取任务启动时刻。
- 多个主题满足一个即可。在评论、主评论、帖子三个层级依次查找，结果的 `topicSource` 会说明命中了哪一层。省略主题可读取所有主题的候选。
- 默认筛选提问、抱怨和建议。一条评论可以同时有多个标签。`--kind 提问` 可单独使用。具体筛选词、排除项及分类表在 `classify.js`。
- 默认每个列表最多读取 100 页，单帖截图最多浏览 180 步，可通过 `--max-pages`、`--steps` 调整。`--out` 指定结果所在的父目录，每次执行自动创建独立子目录。
- 登录态存放在 `~/.weibo-comment-reader/chrome`，可用 `--profile` 指定其他专用目录。`login` 和 `scan` 应使用同一个目录。

## 在其他 Agent 中调用

调用方传入已经登录微博的 Playwright BrowserContext。此函数仅关闭自己创建的取证标签页。

```js
const { runAgent } = require('./agent');

async function collectWeibo(context, postUrl) {
  const { directory, result } = await runAgent(context, {
    posts: [postUrl],
    kinds: ['提问', '抱怨'],
    topics: ['增程器', '亏电', '保养'],
    out: './weibo-runs'
  });
  return { directory, status: result.status, posts: result.posts };
}
```

| 核心文件 | 修改位置 |
| --- | --- |
| `reader.js` | `discover` 遍历账号时间线；`readPost` 核验原帖、读取热度和时间两种排序，再按主评论 ID 分页读取楼中楼；`pages` 处理末页、重复游标和页数上限。 |
| `classify.js` | `classify` 决定意图、主题和分类；`finishPost` 将计数差额、缺图或读取异常计入状态。 |
| `evidence.js` | `captureEvidence` 处理原帖、滚动和回复弹窗；`pageView` 集中存放网页选择器与可见性检查。 |
| `agent.js` | `runAgent` 串起发现、读取、筛选、截图及结果写入。若已有自己的报告系统，可直接使用返回的结构化结果。 |

## 怎样核对一次运行

- **result.json** 保存本次任务范围、待处理链接、每帖每种排序及楼中楼的页数和停止原因、去重后的全部原话和筛选结果。每条评论记录平台 ID、作者、时间、原帖链接、所属主评论 ID，以及网页提供的被回复评论 ID。已截图记录还包含 PNG 路径、SHA-256、截图时刻和评论所在的屏幕矩形。
- **review.html** 按原帖、类别列出入选原话，楼中楼带上主评论上下文。可以点击原帖或直接打开本地整屏图片。缺图项显示“待补原页截图”。
- **evidence/** 图片以“帖子 ID-评论 ID.png”命名。转交报告时保留同级图片目录。
- **完成口径** 只有两种排序及发现的楼中楼均走到末页、平台计数与唯一评论数一致、入选项均取得截图时，才标记“已核对本次可见范围”。平台计数可能包含已删除或当前账号不可见的内容。缺口及登录、限流等中断写入结果，退出码为 2。账号时段无帖和原帖有评论但无筛选命中有不同记录。
- **人工复核** 本地规则产生候选，语义隐晦的抱怨可能漏选，借用整帖主题也可能引入无关跟帖。可直接对 `result.json` 内保留的全部评论重新筛选。评论随时间变化，每次运行看到的是当时会话下可访问的数据。

## 验证

在项目目录运行 `npm test`。回归用例使用本地构造的数据和实际 Chrome，覆盖分页、楼中楼、同文异人、原图取证、缺图、日期边界和访问受限。测试数据只在临时目录使用。

该版本另外对历史原帖做过匿名连通性检查，微博返回 HTTP 403。已登录真实账号的在线全链路尚待验证。微博网页接口的字段、排序参数和页面选择器可能变化，适配位置分别在 `reader.js` 和 `evidence.js`。
